# 建筑资质公开信息监测与归档系统 V3.1 详细设计

## 一、阶段目标

V3.1 是资质智能化能力的本地 MVP，不进入自动匹配和报告生成，先完成两类可维护数据：

- 资质标准库：维护资质编码、名称、类别、等级、主管单位、来源文件、来源地址和结构化条件。
- 企业档案：维护企业基础资料、已有资质、人员证书和项目业绩。

本阶段用于验证后续 V3.2 资质条件匹配、V3.3 企业资质报告生成的数据基础是否可行。

## 二、范围边界

本阶段包含：

- 后台页面新增 `资质标准` 和 `企业档案`。
- 支持新增资质标准和标准条件。
- 支持新增企业、企业已有资质、企业人员证书、项目业绩。
- 支持本地数据库迁移和 Windows 运行。
- 提供 `zhengfudata v3-acceptance-check` 本地验收命令。

本阶段不包含：

- 自动从政府公告中抽取资质标准。
- 企业资料批量导入。
- 自动判断企业是否满足资质标准。
- 自动生成资质申请报告。
- 多人权限和审批流。

## 三、数据模型

### 资质标准库

`qualification_standards`

- `code`：标准编码，唯一。
- `name`：标准名称。
- `category`：资质类别。
- `level`：资质等级。
- `region`：适用地区。
- `authority`：主管单位。
- `version`：版本。
- `source_url`：来源地址。
- `source_document_title`：来源文件标题。
- `effective_date`：生效日期。
- `summary`：摘要。
- `remark`：备注。

`qualification_standard_conditions`

- `standard_id`：关联资质标准。
- `condition_type`：条件类型，支持资产、人员、业绩、设备、其他。
- `title`：条件名称。
- `requirement_text`：要求正文。
- `metric_name`、`metric_value`、`metric_unit`：可选结构化指标。
- `sort_order`：排序。

### 企业档案

`enterprises`

- 企业名称、统一社会信用代码、法定代表人、地区、注册资本、联系人、联系电话、地址、备注。

`enterprise_qualifications`

- 企业已有资质、资质类别、等级、证书编号、发证机关、有效期、可选关联标准。

`enterprise_personnel`

- 人员姓名、脱敏证件号、人员类型、证书名称、证书编号、专业、等级、有效期。

`enterprise_projects`

- 项目名称、项目类型、合同金额、完成日期、企业角色、来源文件、备注。

## 四、后台页面

- `/qualification-standards`：标准列表、新增标准、按编码/名称/类别搜索。
- `/qualification-standards/{id}`：标准详情、条件列表、新增条件。
- `/enterprises`：企业列表、新增企业、按企业名称/信用代码/地区搜索。
- `/enterprises/{id}`：企业详情、新增已有资质、人员证书、项目业绩。

## 五、验收方式

本地命令：

```bash
zhengfudata v3-acceptance-check
```

Windows 脚本：

```powershell
scripts\windows\v3-acceptance-check.ps1
```

验收命令会检查：

- V3.1 六张表是否存在。
- 能否写入并读取资质标准和标准条件。
- 能否写入并读取企业档案、已有资质、人员证书、项目业绩。
- 能否生成 `storage/exports/v3_1_acceptance_report_*.md` 验收报告。

通过标准：

- 命令退出码为 0。
- 输出包含 `summary ok=3 fail=0`。
- 后台可访问 `资质标准` 和 `企业档案` 页面。
- 页面新增数据后，刷新仍可查询和查看详情。
